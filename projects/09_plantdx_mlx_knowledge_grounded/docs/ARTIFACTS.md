# Artifacts: what is in git, what must be downloaded, what is generated, what is missing

Everything the two MLX models (`qwen25vl_tomato_qlora`, `qwen25vl_mango_qlora`) and the earlier experiments need,
with where it comes from. Paths are relative to `projects/09_plantdx_mlx_knowledge_grounded/`. This project uses
**no Git LFS**: every file below that is "in git" is a normal git file, and a fresh clone has it.

## Generated by running the pipeline (not in git)

| Artifact | Command | Notes |
|---|---|---|
| `datasets/<crop>/processed/` | `plantdx normalize` | normalized copies of the raw images; checksums tomato `b9556420…` (18,160), mango `6fa29822…` (4,000); gitignored |
| `artifacts/training/<run>/dataset/*.jsonl` with this machine's paths | `plantdx prepare-training --config configs/train/<run config>` | overwrites the July copies in place; their content is identical except the image-path prefix (verified 31 Oct 2026) |
| `checkpoints/<run>/adapters.safetensors` and `NNNNNNN_adapters.safetensors` snapshots | `plantdx train` | `*.safetensors` is gitignored at the repository root |
| New evaluation reports | `plantdx evaluate` | written to `reports/<run>/evaluation/` unless `--output-dir` is given |

## If the adapters are found or retrained

The handover keeps large weights out of git and serves them from `github.com/iAakash1/TIH-IoT` (Git LFS) through
`setup/download_models.py` and `setup/models_manifest.json` at the repository root. To publish an adapter the same
way: commit it to TIH-IoT under `2026-07_July/` (`*.safetensors` is LFS-tracked there), then add an entry with
`path` (here: `projects/09_plantdx_mlx_knowledge_grounded/checkpoints/<run>/adapters.safetensors`), `source`,
`bytes` and `sha256` to the manifest. Each adapter holds 40,370,176 trainable parameters.

# Model card: `qwen25vl_tomato_qlora`, PlantDx tomato leaf captioning (MLX)

Every file this model needs, and the exact command for each stage. Paths are relative to the project folder
`projects/09_plantdx_mlx_knowledge_grounded/` (run every command from there). The code is the shared `plantdx`
package; this model is defined entirely by its config, so its files live in the run-named folders the package
reads and writes (`configs/train/`, `artifacts/training/<run>/`, `checkpoints/<run>/`, `logs/<run>/`, `reports/<run>/`).

## 1. Model and purpose

Describes a tomato leaf photo in one diagnostic caption that names the disease and its visible signs (10 classes:
healthy + 9 PlantVillage diseases). Trained 13–14 Jul 2026 on an Apple M4 Pro.

## 2. Architecture and source

| | |
|---|---|
| Base model | [`mlx-community/Qwen2.5-VL-7B-Instruct-4bit`](https://huggingface.co/mlx-community/Qwen2.5-VL-7B-Instruct-4bit): Qwen2.5-VL-7B-Instruct, 4-bit MLX conversion (downloaded from Hugging Face on first use, ~6 GB) |
| Fine-tuning | QLoRA (LoRA on the frozen 4-bit base) with `mlx_vlm.lora`; vision tower frozen; loss on answers only |
| Adapter | rank 16, alpha 32 (scale 2.0), dropout 0.05; applied by mlx-vlm 0.6.4 to q/k/v/o **and** gate/up/down of all 28 language-model layers (196 modules, see `checkpoints/qwen25vl_tomato_qlora/adapter_config.json`); `configs/lora/qlora.yaml` lists only q/k/v/o, but mlx-vlm 0.6.4 ignores that list |
| Trainable parameters | 40,370,176 of 8,292,037,632 (0.487%) |

## 3. Dataset

PlantVillage tomato, 10 classes, in the repository at `tomato/raw/PlantVillage/{train,val}/Tomato___*` (18,160
images). Normalization keeps all 18,160 (checksum `b9556420…`); the training config selects files matching
`*.JPG` (case-sensitive), which gives **18,006 images**: the 153 `.jpg` files (152 late blight, 1 healthy) and one
`.jpeg` file (late blight) are not used. Split by image, seed 20260711: **16,201 train / 895 validation / 910 test**.
Each image gets one (question, answer) pair: the question comes from `assets/training/instructions.json`, the answer from
the frozen 1,966-caption corpus `artifacts/corpus/captions.jsonl` (sha256 `1225eb86…`).

## 4. Dataset preparation

```bash
plantdx normalize                     # tomato/raw + mango/raw -> datasets/<crop>/processed (CPU; not in git)
plantdx prepare-training --config configs/train/qwen25vl_tomato.yaml
```

`prepare-training` writes `artifacts/training/qwen25vl_tomato_qlora/dataset/{train,validation,test}.jsonl` with
absolute image paths for **this** machine, plus `manifest.json` and the plan in `reports/qwen25vl_tomato_qlora/`.
The committed copies of those files are the July originals (image paths start with
`/Users/aakashjawle/Desktop/experiments/`); regenerating them reproduces every row exactly, only the path prefix
changes (verified 31 Oct 2026, see `../../docs/REPRODUCTION.md`). The caption corpus itself is rebuilt with
`plantdx ontology / vocabulary / concepts / generate` (already in `artifacts/`, identical hashes).

## 6. Environment

macOS on Apple Silicon only (MLX). Recorded on the Mac: Python 3.12.13, `mlx` 0.31.2, `mlx-vlm` 0.6.4, `mlx-lm`
0.31.3, `transformers` 5.12.1 (`requirements-mlx.txt`). Metrics need a second environment with the `[eval]` extra
(`scripts/setup_eval_env.sh`); the two are never installed together (`docs/EVALUATION.md`).

```bash
conda create -n vlm python=3.12 -y && conda activate vlm
pip install -e ".[train]" -r requirements-mlx.txt
python scripts/verify_project.py         # checks files, configs, CLI, artifacts (any OS)
```

## 7. Configuration (`configs/train/qwen25vl_tomato.yaml`)

backend `mlx_vlm` · seed 20260711 · LR 1e-4 (config asks cosine with 100 warm-up steps; the `mlx_vlm.lora` command
passed no schedule and the log shows a constant 1e-4) · micro-batch 1 × gradient accumulation 8 · 1 epoch ·
grad clip 1.0 · gradient checkpointing · max sequence 2,048 · images resized to 448 × 448 · split 0.90/0.05/0.05 ·
1 caption per image, at most 200 captions per disease · checkpoint every 200 steps, keep last 3 + best ·
`resume: false` (set `true` to resume from `checkpoints/qwen25vl_tomato_qlora/`).

## 8. Training

```bash
plantdx train --config configs/train/qwen25vl_tomato.yaml --dry-run   # dataset + plan, no training
plantdx train --config configs/train/qwen25vl_tomato.yaml             # runs mlx_vlm.lora
```

The exact `mlx_vlm.lora` command of the July run is in `reports/qwen25vl_tomato_qlora/training_plan.json`; its log is
`logs/qwen25vl_tomato_qlora/train.log` (16,201 iterations, peak memory 7.2 GB, about 12 hours; final loss 0.226).
The retraining of 31 Oct – 1 Nov 2026 ran the same `mlx_vlm.lora` command in 6 h 56 min (median 0.67 it/s, peak
7.2 GB; mean loss of the last 10 reports 0.209, July 0.210): `retrained_2026-11/qwen25vl_tomato_qlora/train.log`.

## 9. Validation

mlx-vlm 0.6.x passes no validation set to its trainer, so no held-out loss is computed during training
(`docs/TRAINING.md`). The validation split is evaluated with the evaluation command, choosing the split:

```bash
plantdx evaluate --stage inference --adapter checkpoints/qwen25vl_tomato_qlora \
                 --dataset artifacts/training/qwen25vl_tomato_qlora/dataset --split validation \
                 --output-dir reports/qwen25vl_tomato_qlora/evaluation_validation
```

The downloadable retrained weights were chosen this way: 15 of the snapshots saved every 200 iterations were
scored on the validation split, and the best by validation macro-F1 (iteration 13,200: 92.6%, 0.904) was then
evaluated once on the test split (`retrained_2026-11/README.md`, "Choosing the tomato snapshot").

## 10. Checkpoint

`checkpoints/qwen25vl_tomato_qlora/` must hold `adapter_config.json` + `adapters.safetensors` side by side (that
directory is what `--adapter` takes). The July run saved `adapters.safetensors` (sha256 `9d4b21f4…`, recorded in
`reports/qwen25vl_tomato_qlora/evaluation/system_info.json`) and a snapshot every 200 steps; none of the weight
files survived on the Mac. The model was therefore retrained with section 8 on 31 Oct – 1 Nov 2026 (same code,
training rows, config and library versions; `adapter_config.json` is byte-identical to July's). The seed fixes only
the data split: `mlx_vlm.lora` 0.6.4 shuffles the examples and initialises LoRA without a seed, so the retrained
weights have a new checksum and different scores (section 14). The downloadable file is the snapshot saved at
iteration 13,200 of the retraining, chosen on the validation split (section 9); the final file of the run
(iteration 16,201) is kept as an optional download:

| File | Bytes | SHA-256 | Stored in |
|---|---:|---|---|
| `adapters.safetensors` (retrained, iteration 13,200) | 161,529,623 | `a501137b0c5eef4346229be888f2cedc135d7e0434f74c6b136b177052860c3f` | `github.com/iAakash1/TIH-IoT`, `2026-07_July/mlx_adapters/qwen25vl_tomato_qlora/` (Git LFS) |
| final file of the retraining, iteration 16,201 (optional) | 161,529,623 | `a4872a5cbbf072caecb5221a613994efd935099b42b10733a8b758e920db3ee0` | the same folder, `final_iteration_16201/` |

`python setup/download_models.py 09_plantdx` (from the repository root) downloads the first into this folder and
checks the checksum; with `--all` it also puts the second into
`retrained_2026-11/qwen25vl_tomato_qlora/final_iteration_16201/`. `python scripts/verify_project.py` reports whether the weights are present and whether they are the
July or the retrained file.

## 11. Inference

```bash
plantdx infer --adapter checkpoints/qwen25vl_tomato_qlora --image path/to/leaf.JPG
plantdx infer --adapter checkpoints/qwen25vl_tomato_qlora --folder path/to/leaves --json
streamlit run streamlit_app.py      # demo app; choose tomato in the sidebar (docs/DEMO_APP.md)
```

## 12. Evaluation

```bash
plantdx evaluate --stage inference --adapter checkpoints/qwen25vl_tomato_qlora \
                 --dataset artifacts/training/qwen25vl_tomato_qlora/dataset \
                 --output-dir reports/qwen25vl_tomato_qlora/evaluation        # MLX env: base + fine-tuned answers
plantdx evaluate --stage analyze --output-dir reports/qwen25vl_tomato_qlora/evaluation   # [eval] env: metrics
```

`--max-samples 20` gives a quick check.

## 13. Input and output

Input: an RGB leaf photo and an instruction (training resized photos to 448 × 448; inference passes the photo to
the Qwen2.5-VL image processor without that resize). Output: one caption, e.g. "This tomato leaf is affected by
early blight, showing brown-to-dark-brown circular lesions with concentric rings (target/bull's-eye), distributed
scattered then coalescing." (the downloadable weights, on a test image). Evaluation parses the disease name from the caption
(`raw/predictions.jsonl` has `image_id`, `ground_truth`, `base_prediction`, `finetuned_prediction`, timings).

Fine-tuned latency on the M4 Pro: median 1.34 s per image (p95 1.79 s), peak memory 12.0 GB. Weakest class:
early blight (F1 0.79). Figures: `reports/qwen25vl_tomato_qlora/evaluation/figures/`.

The final file of the retraining scores lower because of healthy leaves (F1 0.29: 31 of 80 answers are the single
word "A", 17 describe a healthy leaf without the word "healthy"). The downloadable iteration-13,200 snapshot gets 67
of 80 healthy leaves right (F1 0.91) and one answer names no class, but it is weaker than July on spider mites
(F1 0.82), leaf mold (0.85), mosaic virus (0.84) and target spot (0.79); median latency 1.28 s (p95 1.96 s).
Details and the full evaluations: `retrained_2026-11/README.md`.

## 15. Limitations and hardware

- Needs macOS on Apple Silicon; tested on an M4 Pro with 24 GB (training peak 7.2 GB, evaluation peak 12 GB).
  Not runnable on Windows, Linux or CUDA. The CPU-only steps (normalize, prepare-training, the caption pipeline,
  the test suite) also run on Windows.
- The July weights are lost; the downloadable weights are the retrained ones (section 10), whose scores differ
  slightly from July (section 14).
- PlantVillage photos are lab images on plain backgrounds; field performance was not measured.

# Retraining of both MLX models (31 Oct – 1 Nov 2026)

The adapter weights trained in July 2026 (`adapters.safetensors`, sha256 tomato `9d4b21f4…`, mango `c944488f…`)
were no longer on the Mac at the handover. Both models were therefore trained again on the same Mac, and the new
weights are the ones `setup/download_models.py` provides. This folder holds the logs, plans and full evaluations of
the retraining. The July records in `../logs/` and `../reports/` are unchanged.

## What was kept the same

| | July 2026 | Retraining |
|---|---|---|
| Code | `plantdx`, commit `9f08d99` of github.com/iAakash1/experimentation | the same commit |
| Training rows | `../artifacts/training/<run>/dataset/` | regenerated by `plantdx normalize` + `prepare-training`; train, validation and test of both crops identical row for row (only the image-path prefix differs) |
| Training command | `../reports/<run>/training_plan.json` | the same `mlx_vlm.lora` arguments (`<run>/training_plan.json`; only the Python interpreter path differs) |
| `adapter_config.json` | `../checkpoints/<run>/` | byte-identical |
| Libraries (training and inference) | `mlx` 0.31.2, `mlx-vlm` 0.6.4, `mlx-lm` 0.31.3, `transformers` 5.12.1, `torch` 2.13.0, Python 3.12.13 | the same, Python 3.12.0 |
| Hardware | Apple M4 Pro, 24 GB, macOS 26.5.2 | the same Mac, macOS 27.0.1 |

**What differs between runs.** The seed 20260711 fixes the train/validation/test split. `mlx_vlm.lora` 0.6.4 takes
no seed: the order of the training examples (`np.random.permutation` in `mlx_vlm/trainer/sft_trainer.py`), the
LoRA initialisation and dropout are random in every run. Two runs on identical data therefore give different
weights and somewhat different scores.

### Where the two runs differ

**Tomato healthy leaves** (80 test images) explain the lower tomato score: 14 correct (July 77), 18 called a disease
(13 target spot, 4 spider mites, 1 late blight), 31 answers of a single word ("A" or "A."), and 17 answers that
describe a healthy leaf without the word "healthy" ("A normal tomato leaf with uniform green lamina.", "A tomato
leaf with no pathology.") and are therefore not mapped to a class by the evaluation's parser. Per-disease F1 of the
nine diseases is close to July: 0.83–0.99 (July 0.79–0.99); early blight improved from 0.79 to 0.83.

## Commands that produced this folder

```bash
plantdx train --config configs/train/qwen25vl_tomato.yaml
plantdx train --config configs/train/qwen25vl_mango.yaml --crop mango
# per crop, MLX environment:
plantdx evaluate --stage inference --adapter checkpoints/qwen25vl_<crop>_qlora \
                 --dataset artifacts/training/qwen25vl_<crop>_qlora/dataset --output-dir <out>
# per crop, metrics environment (.venv-eval):
plantdx evaluate --stage analyze --adapter checkpoints/qwen25vl_<crop>_qlora \
                 --dataset artifacts/training/qwen25vl_<crop>_qlora/dataset --output-dir <out>
```

The metrics environment had `transformers` 5.22.1 and `torch` 2.15.0 (`evaluation/system_info.json`); the base
rows above match July to within one image, so the scoring is consistent.
